# Артефакты исследования

Помимо научных статей snowcite принимает ваш собственный материал — расшифровки интервью, код, архивные документы, заметки, описания датасетов — и позволяет цитировать его рядом с литературой.

## Типы

| Тип | Что это | Типичное применение |
|---|---|---|
| `interview` | Расшифровка разговора | Цитаты в результатах и обсуждении |
| `code` | Файл или фрагмент кода | Методология |
| `document` | Архивный текст, письмо, внутренний документ | Цитируется как первоисточник |
| `note` | Свободная исследовательская заметка | Фон, обсуждение |
| `dataset` | Описание датасета (не сами данные) | Методология, доступность данных |

Поддерживается только UTF-8 текст. PDF и `.docx` сначала конвертируйте (`pdftotext`, pandoc).

## Инструменты

- `add_artifact(type, label, path=... | content=..., summary, metadata)` — из файла или из текста, набранного в чате. Возвращает id и `citation_label`.
- `get_artifacts()` — краткие записи без текста; `get_artifacts(id)` — полный текст для цитирования. Фильтры: `type`, `included_only`.
- `update_artifact(id, included=False)` — исключить, не теряя; `delete=True` удаляет насовсем.

Лимит: около 200 000 символов на артефакт. Большее — разбейте.

## Цитирование

Метки короткие: `[I:3]` интервью 3, `[C:auth.py]` код (имена, похожие на имя файла, берутся как есть), `[D:5]` документ, `[N:2]` заметка, `[DS:1]` датасет. Держите их единообразными по всему документу. Входы критики секции перечисляют все включённые артефакты краткими записями, поэтому рецензент может сверить цитату с `get_artifacts(id)` посимвольно.

## Чего он не делает

Нет расшифровки аудио, разбора PDF и docx, анализа данных и сборки документа. Цитата, приписанная участнику, должна дословно присутствовать в артефакте — критик помечает всё остальное как фабрикацию.
